
# Google Giriş Yeniden Teşhis Notu

25 Ağustos 2026 canlı testinde `https://6lory.vercel.app/?login-debug=1` ana sayfası Google giriş düğmesiyle yüklendi. Düğmeye basınca tarayıcı `https://6loryapp-pernhdey.manus.space/?login=1&next=%2F%3Flogin-debug%3D1` adresine yöneldi ve ekran boş kaldı; sonraki tarayıcı görünüm çağrısı da oturumun yönlendirme sırasında kullanılamadığını bildirdi. Bu bulgu, arızanın Google hesap seçicisinden önceki Vercel→yönetilen `login=1` köprüsünde veya onun ilk JavaScript yüklenmesinde oluştuğunu gösterir; callback aşamasına henüz ulaşılmadı.
Yeniden üretimde yönetilen `https://6loryapp-pernhdey.manus.space/?login=1&next=%2F` adresi, nonce/state içeren `/app-auth` URL’sine yönlendi ve Manus hesap seçici `socialtrade / socialtradeturkey@gmail.com` ile görünür biçimde yüklendi. Bu nedenle köprü ve provider başlangıcı çalışıyor; ilk boş ekran gözlemi yönlendirme sırasında alınmış geçiş ekranı olabilir. Asıl doğrulama için hesap seçimi sonrası callback, session cookie ve hedef rota izlenecek.
Hesap seçici üzerinde mevcut `socialtrade` hesabı seçildikten sonra tarayıcı yönetilen kök adrese döndü (`https://6loryapp-pernhdey.manus.space/`), ancak geçiş anında ekran boş göründü ve hemen sonraki görünüm çağrısı tarayıcı oturumunun kullanılamadığını bildirdi. Callback sonucunu bu gözlemle tek başına doğrulamak mümkün olmadı; sonraki adım ağ/console logları ve doğrudan callback yanıtını incelemektir.
Hesap seçiminden sonra aynı yönetilen origin’e doğrudan `?oauth-recheck=1` ile gidildiğinde oturumlu kullanıcı arayüzü başarıyla yüklendi: `Çıkış yap`, `Hoş geldiniz`, `socialtrade` ve dashboard sayaçları görüldü. Bu canlı deneme callback → session cookie → yönetilen ana sayfa zincirinin çalıştığını gösteriyor. Vercel origin’i oturum cookie’sini paylaşmadığı için giriş sonrası hedefin yönetilen alan olması beklenen güvenlik davranışıdır.
Yönetilen production sayfasında tarayıcı console kontrolü, aktif controller’ın `https://6loryapp-pernhdey.manus.space/sw.js` olduğunu, registration state’inin `activated` olduğunu ve `6lory-shell-v3` cache’inin bulunduğunu gösterdi. Service worker güncel kaynakta network-first navigation ve sürüm cache temizliği uyguluyor; yine de canlı kullanıcıda eski SW controller’ı ilk ziyaret sonrası tutulabildiği için OAuth girişinde stale shell ihtimali ayrıca giderilmelidir.
Canlı managed console’da `6lory-shell-v3` cache’inde birden fazla eski `index-*.js/css` paketi bulundu; güncel network HTML ise `/assets/index-Cn_8YuAH.js` paketini çağırıyor. HTML’nin kendisi güvenli giriş durum metnini içermiyor (bu metin JavaScript tarafından ekleniyor). Bu, service worker’ın exact URL cache eşleşmesiyle eski JS paketi sunması halinde `login=1` bridge davranışının sürüme göre değişebileceğini gösteren güçlü bir canlı bulgudur.
Canlı tarayıcı console geçmişinde Google giriş denemesiyle ilişkili JavaScript istisnası veya API hatası görünmedi; yönetilen root, oturumlu UI’yı sunuyor. Cache ve network HTML aynı `index-Cn_8YuAH.js` paketini referanslıyor. Runtime error raporunda da son 24 saatte Vercel için hata yok. Sorun bu nedenle sistematik callback çökmesi değil; kullanıcı deneyiminde yönlendirme geçişinin boş/yanıt vermiyor algılanması veya kullanıcının Vercel’de yönetilen origin’e geçişi fark etmemesi olasılığı yükseldi.
Yeni checkpoint sonrası Vercel `https://6lory.vercel.app/?login=1&next=%2F` denemesi Manus hesap seçicisine ulaştı; kayıtlı `socialtrade` hesabı seçilince callback tamamlandı ve `https://6loryapp-pernhdey.manus.space/` managed ana sayfasına döndü. Böylece Vercel→hesap seçici→callback→oturum→hedef rota canlı zinciri tekrar başarılıdır.
Google giriş düzeltmesi managed checkpoint `12de7be5` ile yayımlandı. Vercel production deployment `dpl_6wXXbe9muw8E8hsF4DA3awbZt5Ey` `READY` durumuna ulaştı ve `6lory.vercel.app` alias’ını aldı.
